## Two planes, one model

<CardGrid>
	<Card title="Control plane" icon="setting">
		`guru-master` serves the operator API, the worker API, the AMQP hooks that derive configs and
		run every periodic job, and the clock that schedules them — one binary, four modes.
	</Card>
	<Card title="Data plane" icon="rocket">
		`guru-worker` terminates listeners and forwards traffic, either from a local TOML file or by
		streaming configs from the master.
	</Card>
	<Card title="Convergent rollout" icon="approve-check">
		Every server keeps `desired`, `in_flight` and `applied` snapshots, so no revision drops
		traffic mid-rollout.
	</Card>
	<Card title="Everything is a Processor" icon="puzzle">
		State plus an async function. Each query, operation and consumer is an input struct with one
		`Processor` impl.
	</Card>
</CardGrid>
