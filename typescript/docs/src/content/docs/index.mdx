## Two planes, one model

<CardGrid>
	<Card title="Control plane" icon="setting">
		`guru-master` serves the operator API, the worker API, the AMQP hooks that derive configs and
		run every periodic job, and the clock that schedules them — one binary, four modes.
	</Card>
	<Card title="Data plane" icon="rocket">
		`guru-worker` terminates listeners and forwards traffic, either from a local TOML file or by
		streaming configs from the master.
	</Card>
	<Card title="Everything is in real-time" icon="bars">
		Every mutation goes on a live bus, so the canvas, the health page and its pod events update in
		place — no polling, no reload — while workers stream their configs and push their own health.
	</Card>
	<Card title="Single Entry Microservices with BFF" icon="puzzle">
		One feature module per concern, mounted behind a single gRPC entry point, with the dashboard as
		the only browser-facing surface: its server calls gRPC, the browser never does.
	</Card>
</CardGrid>
