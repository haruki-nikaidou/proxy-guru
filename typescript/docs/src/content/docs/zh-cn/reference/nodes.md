画布上有两种卡片。**带着各自 Pod 的服务器、出口和子画布**是存储的：它们是控制平面保存的行，编辑其中之一就是
编辑这张图。**分流器、聚合器和传送门**则是每次绘制画布时从这张图算出来的，为的是让庞大的转发网络仍然读得懂。
这一页讲的是这套词汇；承载这些卡片的画面以及编辑它们的操作见[画布](/zh-cn/reference/canvas/)。

## 模型

| 概念 | 是什么 |
|---|---|
| **服务器** | 一台运行 `guru-worker` 的机器，也是在它上面运行的 Pod 的集合。服务器本身不转发任何东西。 |
| **Pod** | 某台服务器上的一个监听：一个端口、可选的绑定地址、可选的对外地址，以及它的**接入方式**。每个 Pod 都是一个独立的顶点。 |
| **接入方式** | 流量到达 Pod 的方式。*客户端* Pod 直接接受客户端连接 —— 裸 TCP，或用 ACME 证书终结 TLS —— 并可以接收 PROXY 头。*中继* Pod 接受其他 Pod 经由 TCP、TLS 或 QUIC 中继过来的流量。 |
| **出口** | 转发网络之外、流量离开的 `host:port`，可以附带 PROXY 头。任意多个 Pod 都可以连到同一个出口。 |
| **边** | Pod 流量的一条去向：去往某个中继 Pod，或某个出口。两个 Pod 之间可以有多条边（比如拨不同的地址）。连向 Pod 的边还带着它拨号用的 IP 版本：自动、IPv4 或 IPv6。 |
| **路由** | 每个 Pod 自己的一棵树，叶子恰好是它自己的出边。**负载均衡**按权重把连接分给成员，**故障转移**使用第一个存活的成员。两者可以任意层数互相嵌套。 |

由这个模型可以得出几条规则：

- **一跳的协议由目标的接入方式决定。** 连向 `relay_quic` Pod 的边就是一跳 QUIC；改变 Pod 的接入方式，所有连向
  它的 Pod 都会按新的方式拨号。
- **一跳的地址**依次取边上的覆盖地址、目标 Pod 的对外地址、目标服务器的有效地址（从 Worker 学到的：固定、上报
  或观测；服务器有 IPv4 就是 IPv4）。边设成 **IPv4** 或 **IPv6** 时改拨那个版本：对外地址只有属于这个版本才用，
  否则拨服务器这个版本的地址。服务器没有这个版本的地址时，拨号的 Pod 保持正在跑的配置，画布给出警告
  （`dial_family_unreachable`）。端口依次取边上的覆盖端口、目标 Pod 的端口。
- **客户端 Pod 不能被连入**，流量也永远不会回到它已经经过的 Pod：图始终无环。
- **端口可以自动分配。** 保存时不填端口的 Pod 会得到所在服务器 40000–59999 之间的一个空闲端口；同一台服务器的
  两个 Pod 不能占用同一个套接字（通配绑定与该端口、该传输层上的所有地址重叠）。
- **按客户端 IP 固定的负载均衡**需要知道客户端地址的 Pod：中继 Pod，或接收 PROXY 的客户端 Pod。
- **画了一半也是合法的。** 没有去向的 Pod、没有被连入的中继 Pod、没有边到达的出口都只是警告；这样的 Pod 只是
  不会部署，不影响其他任何东西。

## 服务器

![guru-test-sg 的服务器卡片：新加坡国旗、绿色的 Online 徽标、IPv4 地址、最后一次上报和 Worker 版本，以及三个客户端 Pod —— 走原始 TCP 的 direct 和 plain、终结 TLS 的 web —— 及其监听地址，每个都带一个蓝色把手](/img/canvas/card-server-client.avif)

服务器卡片显示健康徽标、其他服务器拨它时用的地址、最后一次健康上报的时间和 Worker 版本，然后是画在这个画布上的
每个 Pod 各一行：经过它的规则的颜色、名字、接入方式（客户端 Pod 带一个进入方框的箭头）和监听地址。

![guru-test-us-1 的服务器卡片：两个 QUIC 中继 Pod plain 和 web，每个左边有一个红色把手、右边有一个蓝色把手](/img/canvas/card-server-relay.avif)

每个 Pod 行的**右侧**都有一个蓝色把手：这个 Pod 的线从这里出发，从这里拖出就给它加一个新的去向。中继 Pod 的行在
**左侧**还有一个红色把手，连向这个 Pod 的线落在这里，去向也可以放在这里。卡片标题上的红色把手会把去向落成这台服务器
上的一个新中继 Pod。其他画布的服务器、但它的 Pod 画在这个画布上时，会以虚线边框显示。

服务器的面板里有它的设置（名称、图标、日志级别、IPv6 策略、QUIC 速率、固定地址和额外地址）、它的 Pod 列表和添加
Pod 的一行、在它上面运行的 agent，以及它在发布中的状态。

## 分流器

![分流器卡片：负载均衡，2 个路由，guru-test-us-1 和 example.com 两个成员及其权重，以及 + 成员 把手](/img/canvas/card-splitter.avif)

分流器是路由中的一个分组 —— 负载均衡或故障转移。在相同的卡片之间以相同方式选择的分组，不论属于多少个 Pod，都画成
**一个**分流器：两条规则在同一台中继服务器和同一个出口之间做负载均衡，就是一个代表两个路由的分流器。每一行是一个成员，带着它的权重
（`×2`）或档位（`#1`）以及去向；成员本身是分组时，会连向一个嵌套的分流器。**+ 成员** 把手会给这个分流器
代表的每个路由都加一个成员；从某个成员行拖出，则给每个路由里的这个成员加上去向。它的面板可以一次性修改所有这些
路由的策略、固定方式、权重和顺序。

## 聚合器

![聚合器卡片：2 台服务器，一个去向，到 example.com](/img/canvas/card-aggregator.avif)

当来自两台及以上服务器的总线在同一个分流器或出口前汇合时，聚合器把它们收拢，并为每张交出去的卡片各设一个出口。
它只是画法：不保存任何东西，也不能编辑或删除。但从它的某个去向行拖出，可以一次给这一行上的每个 Pod 加上去向
（见[连接](/zh-cn/reference/canvas/#连接)）。

## 子画布与传送门

子画布是这棵树里的一个画布，被画成另一个画布中的一张卡片；**传送门**卡片则代表树中另一个画布，这个画布的边连
进去或从那里连过来。两者都只是导航，不是拓扑 —— 嵌套改变什么、不改变什么，见
[画布树](/zh-cn/reference/canvas/#画布树)。

## Pod 的面板与它的路由

![plain 的 Pod 面板：端口、绑定和对外地址，以及显示在 guru-test-us-1 的中继 Pod 与出口 example.com 之间负载均衡的路由编辑器](/img/canvas/panel-route.avif)

点击 Pod 行打开它的面板：名字和备注、接入方式、是否接收 PROXY、TLS 客户端 Pod 的 TLS 证书（SNI、DNS 提供商、
zone 或域名 id、ACME 目录）、端口、绑定地址和对外地址。下面是树形的路由：

- 每个分组有一个策略（负载均衡或故障转移），负载均衡可以按客户端地址固定；
- 负载均衡的每个成员有权重，故障转移的每个成员有档位；
- 箭头用来调整成员顺序；勾选一个分组中的两个或更多成员，可以把它们**编组**成自己的负载均衡或故障转移，
  **解散编组**把嵌套的分组放回父分组；
- **添加去向**给这个分组加一个成员（与[连接](/zh-cn/reference/canvas/#连接)相同的目标对话框）；
- 去向的菜单可以编辑这条边的**拨号地址** —— 覆盖地址或端口，以及拨号用的 IP 版本 —— 或删除这个去向。

路由的结构在保存之前都是草稿。添加或删除去向会改变边、立即写入，所以要等草稿保存或还原之后才能做。中继 Pod 的面板
还会列出连向它的 Pod。

每个 Pod 最终在其服务器的配置里变成一个 `[[forwarding]]`，tag 是 Pod 的 id，它的路由则变成该 Worker 在其中
做选择的上游表 —— 见[发布](/zh-cn/reference/rollout/#转发形态)。
