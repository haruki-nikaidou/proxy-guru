一棵画布树持有一张 **Pod 图**：一张有向无环图，顶点是服务器上的监听，终点是转发网络之外的目的地。每次编辑时，
控制平面都会检查整张图，并由它为每台服务器派生一份配置（见[发布](/zh-cn/reference/rollout/)）。画布就是这张图
的画法，也是唯一能编辑它的地方；画布上的卡片见[节点](/zh-cn/reference/nodes/)。

![main 画布：新加坡的服务器上有三个客户端 Pod，其中两个各自用一条线进入同一个分流器，在美国服务器上的中继 Pod 和出口本身之间做负载均衡，第三个直接去往出口；一个聚合器把来自两台服务器的线汇合到出口 example.com](/img/canvas/canvas-overview.avif)

## 存储与绘制

控制平面保存的东西很少：带着各自 Pod 的服务器、出口、子画布、每个去向一条边、每个 Pod 一棵路由树，以及每张
卡片放在哪里。画面上的其他一切都是绘制时从这张图算出来的，正因如此，一张有四十条边的转发网络画出来也只有
几张卡片。

![上下两块面板展示同一套拓扑。上面是存储的内容：一台新加坡服务器带着客户端 Pod plain、web 和 direct，一台美国服务器带着中继 Pod plain 和 web，出口 example.com:80，它们之间的七条边，以及两个有两个去向的 Pod 各自的一棵负载均衡路由。下面是画出来的样子：同样的服务器和出口，但从 plain 和 web 出来的线进入同一个代表 2 个路由的「负载均衡」分流器，从它通往美国服务器的线缆是一条代表 2 条边的总线，出口前面的线则汇合到一个跨 2 台服务器的聚合器里](/img/canvas/graph-vs-drawing.svg)

分流器代表路由里的分组，聚合器代表汇合的线，总线代表走同一条路的边。它们都没有自己的存储行：随着图的变化，
它们会出现、合并、消失 —— 这既是它们不能被删除的原因，也是一张分流器卡片可以同时属于许多 Pod 的原因。

## 总线与规则

**总线**是在两个把手之间走同一条路的所有边，画成一根线缆，里面每条**规则**各有一根该规则颜色的细线，代表多条边时
还会标出数量。线从蓝色把手出发，落在红色把手上：Pod 的线从它自己那一行出发，落到它拨号的中继 Pod 那一行，或者落到
分流器、聚合器、出口、子画布上。同一台服务器上两个 Pod 之间的线，会从卡片下方绕过去。

规则就是客户端 Pod —— 流量进入转发网络的地方 —— 它会给这些流量可能经过的一切上色。右上角的图例列出画布上的规则；
点击其中一条，不承载它的东西都会变淡。

点击一条总线会打开它的面板：它从哪里到哪里，其中连向 Pod 的边拨号用的 **IP 版本** —— 自动、IPv4 或 IPv6，一次
改全部（不一致时显示*混合*）—— 控制平面在这些边上发现的问题，走在上面的规则 —— 每条用它细线的颜色显示，并写明
总线里有几条边承载它 —— 以及每条边的 id、它承载的规则、去向和拨号地址。

![从 plain 进入分流器那条线的面板：从 plain · guru-test-sg 到 Balance，一条规则走在 2 条边上，以及连向 guru-test-us-1 上中继 Pod plain 和连向 example.com 的两条边，每条都带着连线 ID](/img/canvas/panel-bus.avif)

## 画布树

一个画布可以作为子画布卡片画在另一个画布里，双击即可进入。嵌套只用来组织画面：边可以自由跨越画布边界，而控制
平面检查并据以派生的那张图是整棵树，不是某一个画布。把连线拖到子画布卡片上，会询问指的是其中哪个中继 Pod、
出口或服务器；从树中别处连到的画布会以传送门卡片显示。

## 问题

左下角列出控制平面在这棵树的图上发现的问题 —— 先是与这个画布有关的，再是树中其他地方的。点击一条就打开它所涉及
的东西，如果在别处，会先打开那个画布。错误会阻止下一次编辑；警告从不阻止。

## 编辑

每次编辑都是**一个批次** —— 要写入和删除的行 —— 控制平面会针对它所导致的图整体检查，要么全部写入，要么全部不写。
如果批次是基于一棵在画布读取之后已经改变的树计算出来的，就会被拒绝；画布会重新加载，你再试一次即可。

### 添加

菜单栏的**添加**会在视图中央附近、不与其他卡片重叠的地方创建服务器、出口（会询问目的地）或子画布。Pod 在服务器的
面板里添加：名字、接入方式和端口 —— 留空就自动分配。

### 连接

从 Pod 行右侧的蓝色把手拖出，放到下面某个红色把手上：

| 放到 | 结果 |
|---|---|
| 某个中继 Pod 的那一行 | 一条连向该 Pod 的边 |
| 某个出口 | 一条连向该出口的边 |
| 某张服务器卡片的标题 | 那台服务器上一个新的中继 Pod，按你选的协议监听 |
| 某个分流器 | 这个 Pod 加入它：它的路由多出一份该分流器分组的副本，落在同样那些服务器上属于它自己的中继 Pod 上。这些中继 Pod 还没有去向：连好其中一个，提示里可以把其余的也连上 |
| 某个子画布或传送门 | 由你选择其中的中继 Pod、出口，或某台服务器上的新中继 Pod |

新的去向会加入 Pod 的路由：第一个就是整个路由，第二个会把两者变成负载均衡，分组则多一个成员。从分流器的 **+ 成员**
把手拖出，会对它代表的每个路由做同样的事。

画出来的卡片上的行也能拖出，一次放下就作用到这一行背后的每个 Pod：

| 从这里拖出 | 加上去向的是 |
|---|---|
| 分流器的某个成员行 | 分流器代表的每个路由里的这个成员 |
| 聚合器的某个去向行 | 线经过这个去向的每个 Pod |

行能放到的地方和 Pod 行一样，但不能放到分流器上、它已经连着的地方，或它自己的 Pod 上。和单个 Pod 一样，一条边
会变成新旧两者的负载均衡，分组则多一个成员；要故障转移，在分流器的面板里改。从行或 **+ 成员** 拖到服务器标题上时，
同一条规则的 Pod 共用在那里新建的一个中继 Pod：把聚合器的去向行拖到新的出口或服务器上，一条规则的五个中继 Pod
一次连好，并出现一个分流器。

连接一个还没有去向的中继 Pod 时，如果同一分组落地的其他中继 Pod 也都没有去向，提示里会有一个按钮，把它们照样连上。

Pod 自己的路由 —— 它的去向挂在怎样的分组里、各自的权重和拨号地址 —— 在
[Pod 的面板](/zh-cn/reference/nodes/#pod-的面板与它的路由)里编辑。

### 删除

选中卡片或总线后按 **Delete**，或使用面板里的删除按钮。要删除的内容会在删除之前连同控制平面对结果图的判定一起显示：

![确认对话框：删除 2 个 Pod、删除 4 条连线、改写 2 个 Pod、删除服务器 guru-test-us-1，一个“同时删除不再有入边的中继 Pod”的开关，以及控制面接受这次修改](/img/canvas/dialog-review.avif)

删除 Pod 会删除进出它的所有边，并改写引用这些边的路由。**同时删除不再有入边的中继 Pod** 会把不再有任何连入的中继
Pod 连同它们的去向一起删掉 —— 也就是为某条规则落在中转服务器上的那些。删除服务器会先删除它的 Pod；删除子画布会
删除其中的一切，但只要还有外面的 Pod 连进去，或运行在里面的服务器上，就会被拒绝。

### 移动

拖动卡片来移动，松开时位置会被保存。服务器、出口和子画布的位置保存在它们自己的行上。分流器、聚合器、传送门以及
其他画布的服务器记在画布的布局里；编辑会让每张卡片保持原位：被编辑改变了形状的分流器留在原处，新卡片会放在
不与其他卡片重叠的地方。

## 编辑如何被检查

下面这些会拒绝整个批次：

| 问题 | 原因 |
|---|---|
| `cycle` | 流量可能回到它已经经过的 Pod |
| `route_missing_edge`、`route_duplicate_edge`、`route_unknown_edge`、`route_foreign_edge`、`missing_route` | 路由没有恰好各引用一次该 Pod 的每条出边 |
| `empty_group`、`zero_weight`、`route_too_deep` | 没有成员的分组、权重为 0、嵌套超过 32 层 |
| `client_pod_dialed` | 连向客户端 Pod 的边 |
| `listener_conflict` | 同一台服务器的两个 Pod 在同一端口、同一传输层上绑定地址重叠 |
| `listener_in_use` | 某台服务器仍在以另一种协议拨这个端口：改给 Pod 换一个新端口 |
| `sticky_without_client_ip` | 在不知道客户端地址的 Pod 上使用按客户端固定的负载均衡 |
| `invalid_bind_ip`、`invalid_advertise_ip`、`invalid_override_address`、`invalid_exit_destination`、`invalid_sni` | 无法解析的地址、目的地和名字 |
| `unknown_dns_provider`、`certificate_issued_elsewhere` | TLS Pod 引用了不存在的 DNS 提供商，或在 SNI 的签发方式上与另一个 Pod 不一致 |
| `no_free_port` | 该服务器上 40000–59999 的端口全被占用 |
| `edge_ends_changed` | 边的两端就是它的身份：删掉它，再加一条 |

下面这些只是警告：`single_tier_failover`、`pod_without_edges`、`relay_pod_not_dialed`、`exit_not_reached`，
以及 `dial_family_unreachable` —— 设成 IPv4 或 IPv6 的边，目标服务器没有这个版本的地址，或者目标 Pod 只监听
另一个版本。拨向它的 Pod 在能拨通之前保持正在跑的配置。

被接受的批次会递增这棵树的 generation，控制平面则为这次改动涉及的每台服务器派生一份新的配置 —— 接下来发生
什么，见[发布](/zh-cn/reference/rollout/)。
