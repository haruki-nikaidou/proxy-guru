## 两个平面，一套模型

<CardGrid>
	<Card title="控制平面" icon="setting">
		`guru-master` 提供运维 API、Worker API、用于推导配置并运行所有周期任务的 AMQP 钩子，
		以及负责调度它们的时钟 —— 一个二进制文件，四种模式。
	</Card>
	<Card title="数据平面" icon="rocket">
		`guru-worker` 负责终结监听器并转发流量，配置既可以来自本地 TOML 文件，
		也可以从 master 流式下发。
	</Card>
	<Card title="一切都是实时的" icon="bars">
		每一次改动都会走实时总线，所以画布、健康状况页面及其 Pod 事件都会就地更新 —— 不轮询，
		也不刷新页面；同时 Worker 自己也在流式接收配置、主动上报健康状况。
	</Card>
	<Card title="带 BFF 的单入口微服务" icon="puzzle">
		每个关注点一个功能模块，统一挂在单一的 gRPC 入口之后；面向浏览器的只有控制台一个入口，
		而调用 gRPC 的是它的服务端，不是浏览器。
	</Card>
</CardGrid>
