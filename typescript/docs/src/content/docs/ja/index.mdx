## 2つのプレーン、1つのモデル

<CardGrid>
	<Card title="コントロールプレーン" icon="setting">
		`guru-master` は、オペレーター API、ワーカー API、設定を導出して定期ジョブを実行する AMQP フック、
		そしてそれらをスケジュールするクロックを提供します — 1つのバイナリ、4つのモード。
	</Card>
	<Card title="データプレーン" icon="rocket">
		`guru-worker` はリスナーを終端してトラフィックを転送します。ローカルの TOML ファイルから、
		あるいはマスターから設定をストリーミングして動作します。
	</Card>
	<Card title="すべてがリアルタイム" icon="bars">
		あらゆる変更がライブバスに載るので、キャンバス、ヘルスページ、そのポッドイベントはその場で
		更新されます — ポーリングもリロードもありません。ワーカー自身も設定をストリーミングで受け取り、
		自分のヘルスを送り続けます。
	</Card>
	<Card title="BFF を備えた単一入口のマイクロサービス" icon="puzzle">
		関心ごとに 1 つの機能モジュールがあり、それらは単一の gRPC 入口の背後に載ります。ブラウザに
		面するのはダッシュボードだけで、gRPC を呼ぶのはそのサーバーであり、ブラウザではありません。
	</Card>
</CardGrid>
