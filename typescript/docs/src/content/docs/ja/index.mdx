## 2つのプレーン、1つのモデル

<CardGrid>
	<Card title="コントロールプレーン" icon="setting">
		`guru-master` は、オペレーター API、ワーカー API、設定を導出して定期ジョブを実行する AMQP フック、
		そしてそれらをスケジュールするクロックを提供します — 1つのバイナリ、4つのモード。
	</Card>
	<Card title="データプレーン" icon="rocket">
		`guru-worker` はリスナーを終端してトラフィックを転送します。ローカルの TOML ファイルから、
		あるいはマスターから設定をストリーミングして動作します。
	</Card>
	<Card title="収束型ロールアウト" icon="approve-check">
		すべてのサーバーが `desired`、`in_flight`、`applied` のスナップショットを保持するため、
		ロールアウトの途中でリビジョンがトラフィックを落とすことはありません。
	</Card>
	<Card title="すべては Processor" icon="puzzle">
		状態と非同期関数だけです。各クエリ、オペレーション、コンシューマーは、1つの `Processor` 実装を持つ
		入力構造体として表現されます。
	</Card>
</CardGrid>
